## Chen et al - General In-Hand Re-Orientation and Visual Dexterity (curricula and reward design)

**Links:**
- CoRL 2021 / arXiv 2111.03043: https://arxiv.org/abs/2111.03043, source file `research/sources/chen_general_inhand_reorientation_corl21__arxiv_2111.03043.txt`
- Science Robotics / arXiv 2211.11744: https://arxiv.org/abs/2211.11744, source file `research/sources/chen_visual_dexterity__arxiv_2211.11744.txt`

**Type:** papers

**Relevance:** HIGH - both papers are directly about arbitrary-SO(3) in-hand reorientation with dense plus sparse rewards, privileged PPO teachers, relative position actions, hard exploration under gravity, and explicit evidence that curricula/easier initial conditions are load-bearing.

### What it is

These two papers are the most directly relevant MIT/Improbable AI lineage for the failure mode in `LeapXELACubeReorient`: they train multi-finger hands to reorient objects from arbitrary initial orientation to arbitrary goal orientation, and they explicitly discuss the exploration barrier where the robot must simultaneously keep the object in hand and make progress toward a sparse success event.

The CoRL 2021 paper, "A System for General In-Hand Object Re-Orientation", trains simulated Shadow Hand policies in three regimes: upward-facing hand, downward-facing hand with a table, and downward-facing hand in air. Its core recipe is model-free RL for a privileged teacher, optional teacher-student distillation, stable object initialization from successful lifting rollouts, and a hand-designed gravity curriculum. The authors state that the system's three key components are teacher-student learning, gravity curriculum, and stable initialization.

The Visual Dexterity paper extends the same line to a real-world D'Claw-style three/four-finger platform with depth-camera observations. It keeps the teacher-student structure but changes the hard in-air route: all policies are trained in a downward-facing table-top setup, then in-air behavior is induced by a reward penalty for object-table contact plus a four-finger hand. The paper explicitly says prior in-air work needed good-pose initialization and a manually designed gravity curriculum, while their later system avoids separate in-air training by penalizing support-surface contact during table-top training.

The key lesson for the plateau is stark: the authors did not treat arbitrary reorientation as "just PPO plus a dense orientation reward." In the hard downward configuration, direct training from random object poses with the same reward got 0% success. They made the problem easier at the start either by resetting into good grasped poses collected from a separate lifting policy, gradually introducing gravity, or keeping a support surface available while penalizing reliance on it.

### Key technical details

CoRL reward for reorientation is:

`r(s_t, a_t) = c_theta1 * 1/(|Delta theta_t| + epsilon_theta) + c_theta2 * I(|Delta theta_t| < theta_bar) + c3 * ||a_t||_2^2`

The paper defines `Delta theta_t` as the orientation difference between current object orientation and target orientation. It computes quaternion difference `beta = alpha_1 alpha_2^{-1}` and then uses the axis-angle angle of `beta` as the distance between rotations. The coefficient table gives `c_theta1 = 1`, `c_theta2 = 800`, `epsilon_theta = 0.1`, `theta_bar = 0.1 rad`, and `c3 = 0.1`; however, the formula text says `c3 < 0` and describes the term as suppressing large action commands. So the magnitude `0.1` is stated, but the sign is internally inconsistent in the HTML/text. I would treat the intended coefficient as an action penalty of magnitude `0.1`, not a bonus.

CoRL lifting reward, used only to generate good initialization states for downward-in-air reorientation, is:

`r(s_t, a_t) = c_h1 * 1/(|Delta h_t| + epsilon_h) + c_h2 * I(|Delta h_t| < h_bar) + c3 * ||a_t||_2^2`

where `Delta h_t = max(p_t^{b,z} - p_t^{o,z}, 0)`. The table gives `c_h1 = 0.05`, `epsilon_h = 0.02`, `h_bar = 0.04`, `c_h2 = 800`, and again the action coefficient is only listed as `c3 = 0.1` despite the penalty description.

Visual Dexterity reward for table-top reorientation is:

`r_1t = c1 * I(Task successful) + c2 * 1/(|Delta theta_t| + epsilon_theta) + c3 * sum_i ||p_t^{f_i} - p_t^o||_2^2 + c4 * |qdot_t|^T |tau_t| + c5 * I(||p_t^o||_2^2 > p_bar)`

The terms are, respectively: sparse task reward, dense orientation-distance reward, keep fingertips close to the object, energy penalty, and penalty for pushing the object away. The text says `c1, c2 > 0` and `c3, c4, c5 < 0`. Table S1 gives `c1 = 800`, `c2 = 1`, `c3 = -1`, `c4 = -20`, `c5 = -100`, `epsilon_theta = 0.4 radians`, and `p_bar = 0.15`.

Visual Dexterity reward for encouraging in-air behavior while training with a table is:

`r_2t = r_1t + c6 * I(object contacts with the table) + c7 * sum_i I(p_{t,z}^{f_i} > p_bar_z)`

Table S1 gives `c6 = -1`, `c7 = -2`, and `p_bar_z = 0.16`. The contact term exists because a table makes exploration easier but policies trained with support otherwise depend on the support and drop the object when it is removed. The paper says that penalizing object-table contact discourages external support for reorientation; when trained on a support surface with this reward, in-air reorientation emerges. The penultimate-joint/fingertip term is described as not critical, but making behavior more natural-looking.

CoRL success and goal details: for non-vision experiments, success is `Delta theta <= theta_bar` with `theta_bar = 0.1 rad`. Initial and goal orientations are randomly sampled from full `SO(3)` in all experiments. For vision experiments, they also use Chamfer distance to handle symmetry: success is `(Delta theta <= theta_bar) OR (d_C <= d_bar_C)` with `theta_bar = 0.2 rad` and `d_bar_C = 0.01`; both current and goal object point clouds are scaled to fit in a unit sphere for `d_C`.

Visual Dexterity success details: during training, success is not only angular tolerance. It requires all three of: `|Delta theta_t| < theta_bar`, small finger motion, and small object motion. Finger motion requires `||qdot_t|| < qdot_bar` and `||a_t|| < a_bar`; object motion requires `||v_t^o|| < v_bar` and `||omega_t^o|| < omega_bar`. Table S1 gives `qdot_bar = 0.25`, `v_bar = 0.04`, and `omega_bar = 0.5`. The source text does not state numeric `theta_bar` or `a_bar` in Table S1; the paper's evaluation commonly reports `0.4 rad` and `0.8 rad`, and later analyzes `0.1 rad`, but the exact training `theta_bar` value is not stated in the extracted text. In real deployment, they stop when predicted `Delta theta_t < theta_bar` and `||a_t|| < a_bar`; they found only action norm was sufficient for finger motion, and did not estimate object motion in the real world.

CoRL initial/reset distributions: upward-facing setup samples object COM `xy` from a `0.09 m x 0.09 m` square centered near the middle-finger/palm intersection, fixes object `z = 0.13 m` above the hand base to avoid initial collision, and samples initial and goal orientations from full `SO(3)`. Downward-with-table places the tabletop `0.12 m` below the hand base and drops objects in random poses between hand and table. Downward-in-air does not train from arbitrary falling objects; instead, they first train a lifting policy, collect the final states from successful lifting episodes, then reset reorientation episodes to those states with all velocities zero. They collect about `250` ending states per object from successful lifting episodes, containing hand joint positions `q_T`, object position `p_T^o`, and object orientation `alpha_T^o`.

CoRL good-pose/lifting numbers: the lifting policy succeeds at `97.80%` on EGAD and `90.11%` on YCB. With good-pose initialization, downward-in-air reorientation becomes learnable: the paper states EGAD full-state RNN gets more than `80%` success and YCB full-state RNN gets greater than `50%`; Table D.6 gives exact no-DR downward-in-air success rates of EGAD full-state MLP `84.29 +/- 0.9`, EGAD full-state RNN `82.27 +/- 3.3`, EGAD reduced RNN-to-RNN `74.10 +/- 2.3`, YCB full-state MLP `58.95 +/- 2.0`, YCB full-state RNN `52.81 +/- 1.7`, and YCB reduced RNN-to-RNN `45.22 +/- 2.1`.

CoRL gravity curriculum schedule: for YCB downward-in-air, start at `g0 = 1 m s^-1`, evaluate every `L = 20` training iterations, keep a FIFO queue of size `K = 3` of surrogate evaluation success rates, and if `avg(Q) > w_bar = 0.8` and at least `Delta T_min = 40` policy-update iterations have elapsed since the previous gravity change, update gravity by `Delta g = -0.5 m s^-1` until reaching `-9.81 m s^-1`. The algorithm line says `g = max(g - Delta g, -9.81)`, which is inconsistent with `Delta g = -0.5`; the prose says they gradually decrease `g` step-wise from `1` to `-9.81`, so the intended step is `-0.5 m s^-1`.

CoRL gravity curriculum ablation/effect size: for YCB downward-in-air full-state RNN, no curriculum is `52.81 +/- 1.7` and gravity curriculum is `74.74 +/- 1.2`, a gain of `21.93` percentage points. For YCB reduced-state RNN-to-RNN student, no curriculum is `45.22 +/- 2.1` and gravity-curriculum teacher distilled to RNN is `67.33 +/- 1.9`, a gain of `22.11` percentage points. Under randomized-dynamics testing after DR fine-tuning, full-state RNN without curriculum is `40.44 +/- 1.5` while full-state RNN with gravity curriculum is `54.24 +/- 1.4`, a gain of `13.80` points; reduced-state RNN-to-RNN without curriculum is `31.63 +/- 1.6` while gravity-curriculum teacher-to-RNN is `48.58 +/- 2.3`, a gain of `16.95` points. The most extreme ablation is direct downward-facing training from random objects with the same reward: `0%` success, object simply falls.

CoRL action/control details: Shadow Hand has `24` DoF, with `20` actuated joints and `4` under-actuated. The policy action is `a_t in R^20`, commanding relative changes in target joint angle: `q_target_{t+1} = q_target_t + a_t * Delta t`. The command is clamped so `|Delta q_target_t| <= 0.33 rad`. Control frequency is `60 Hz`. Previous action is appended to policy inputs to encourage smoothness.

Visual Dexterity action/control details: three-finger and four-finger hands use `9` and `12` Dynamixel motors, respectively, so the policy action dimension is `3G`. It uses position control at `12 Hz`. The policy outputs relative joint position changes, smoothed with exponential moving average `a_bar_t = alpha a_t + (1-alpha) a_bar_{t-1}`, with `alpha = 0.8`. The next target is `q_tgt_{t+1} = q_t + a_bar_t`. Dynamixel real-world control table parameters are `P = 200` and `D = 10`.

CoRL teacher/student observations: teacher full state is `R^134`, including joint positions `R^24`, joint velocities `R^24`, fingertip positions `R^15`, fingertip orientations `R^20`, fingertip linear velocities `R^15`, fingertip angular velocities `R^15`, object position `R^3`, object orientation quaternion `R^4`, object linear velocity `R^3`, object angular velocity `R^3`, goal orientation quaternion `R^4`, and quaternion difference `R^4`. The teacher does not get object shape, friction, damping, or contact state. Low-dimensional student state is `R^31`: joint positions `R^24`, object position `R^3`, and quaternion difference `R^4`; it does not get velocities. Vision student uses RGBD-derived point cloud plus joint positions and previous action, with goal as the object point cloud in the desired orientation.

Visual Dexterity teacher/student observations: teacher observation is `R^(19G+21)`, including joint positions `R^(3G)`, joint velocities `R^(3G)`, fingertip pose `R^(7G)`, fingertip velocities `R^(6G)`, object pose `R^7`, object velocity `R^6`, target orientation quaternion `R^4`, and relative rotation quaternion `R^4`. Student receives a depth point cloud plus proprioceptive hand point cloud plus goal point cloud; no RGB/color is used in the final described setup. The goal is represented as the object's point cloud in the target orientation. Visual Dexterity explicitly avoids object-pose/keypoint definitions for generalization.

CoRL PPO/training details: non-vision training uses PPO with up to `2` GPUs of `32 GB` memory, `40K` parallel environments, `5` batches, actor learning rate `0.0003`, critic learning rate `0.001`, `8` epochs, GAE `0.95`, discount `0.99`, value loss coefficient `0.0005`, PPO clip `0.1`, episode length `300`, entropy coefficient `0`, rollout steps per update `8` for MLP and `50` for RNN. Student Dagger is online and learns only from latest rollout data. Vision training uses `360` parallel environments, `50` rollout steps per update, batch size `30`, `15000` scene points from `2` cameras, and `5000` goal points from CAD mesh. The source text does not state total environment steps/sample budget for CoRL, except that downward-in-air with DR required enough environment steps that they fine-tuned no-DR models rather than training randomized-dynamics models from scratch.

Visual Dexterity PPO/training details: teacher policy uses PPO with `32000` envs, batch size `64000`, `8` rollout steps per update, GAE lambda `0.95`, reward discount `0.99`, `12` policy update epochs after each rollout, actor learning rate `0.0003`, critic learning rate `0.001`, PPO clip `0.1`, and one NVIDIA RTX 3090 for teacher training. Student uses Stage 1/Stage 2 env counts `400/260`, batch sizes `40/20`, learning rate `0.0003`, `80` rollout steps per policy update, `500` points sampled from each CAD model, and `6000` points from realistically rendered point cloud. Total teacher plus two student stages took less than `400` GPU-hours on a V100-class setup according to their compute-cost section. Stage 1 synthetic point-cloud student training takes less than `3` days; Stage 2 rendered fine-tuning takes about `1` day; training a rendered vision policy from scratch took more than `20` days. The main text also says their two-stage pipeline makes training `5x` faster, while the method section says synthetic Stage 1 is a `7x` speedup over rendering-heavy training.

CoRL object/collision/contact details: the simulator is Isaac Gym. Shadow Hand base is fixed. EGAD has `2282` meshes and YCB has `78` Google-scanned objects; with `5` scaled variants each, training uses `11410` EGAD meshes and `390` YCB meshes. EGAD longest bounding-box side is sampled in `[0.05, 0.08] m`, YCB in `[0.05, 0.12] m`, and mass in `[0.05, 0.15] kg`. The authors use V-HACD approximate convex decomposition for fast collision detection and note the collision meshes remain geometrically different. They do not give contact solver parameters, contact budget, `nconmax`, `njmax`, or fidelity settings.

Visual Dexterity object/collision/contact details: simulator is Isaac Gym rigid-body physics. The Big dataset has `150` training objects; the Small dataset has `12` ContactDB objects with no overlap, with `5` used for real-world OOD evaluation. Longest object bounding-box side lies in `[0.095, 0.165] m`, and object mass is sampled in `[0.03, 0.18] kg`; real evaluation object masses are listed in Table S2. They use V-HACD approximate convex decomposition on object and robot-hand meshes with decomposition resolution `100,000`. They explicitly warn that fast-simulator contact models are crude approximations of reality, especially for non-convex objects. They do not state contact solver budget or equivalent `nconmax`/`njmax`.

Domain randomization in CoRL: state observation noise `+ U(-0.001, 0.001)`, action noise `+ N(0, 0.01)`, object mass multiplier `U(0.5, 1.5)`, object static friction multiplier `U(0.7, 1.3)`, finger static friction multiplier `U(0.7, 1.3)`, joint lower/upper range noise `+ N(0, 0.01)`, joint damping `E(0.3, 3.0)`, joint stiffness `E(0.75, 1.5)`, tendon damping `E(0.3, 3.0)`, and tendon stiffness `E(0.75, 1.5)`, where `E(a,b)=exp(U(log a, log b))`.

Domain randomization in Visual Dexterity: state observation noise is written as `+ N(-0.002, 0.002)` in Table S3, though that notation is odd for Gaussian mean/std; action noise is `+ N(0, 0.05)`, joint stiffness/damping/link mass multipliers are `U(0.8, 1.2)`, friction for robot and objects is `U(0.24, 1.6)`, table friction is `U(0.05, 1.0)`, restitution is `U(0.0, 1.0)`, object size scale is `U(0.95, 1.05)`, and object mass is `U(0.009, 0.324) kg`. At each time step, with probability `p = 0.2`, they apply an object disturbance force of magnitude `F_d^o = c_d m^o`, with `c_d = 15`, in a random SO(3) direction. For point-cloud augmentation, with probability `p = 0.4` they add Gaussian point noise `N(0, 0.004)`, and independently with `p = 0.4` they randomly drop out `q in [0,20]%` of points.

### How it differs from our setup

The biggest difference is task easing. Your current `LeapXELACubeReorient` starts from the stock reset/task structure and tries to learn cube reorientation with a dense orientation reward plus `success_reward = 100` at `success_threshold = 0.1 rad`. CoRL's hardest downward-in-air result did not learn from arbitrary falling/random poses; direct downward training with the same reward got `0%`, then they made resets dramatically easier by sampling from about `250` successful lifted/grasped final states per object and zeroing velocities. Visual Dexterity made exploration easier differently: train with a table always present, but penalize object-table contact to transition away from table reliance.

Your policy/control frequency is `20 Hz` (`ctrl_dt = 0.05`) with relative/integrating target updates `data.ctrl + action * 0.5`. CoRL used `60 Hz` relative position control and clamped each target delta to `0.33 rad`. Visual Dexterity used `12 Hz` but smoothed actions with EMA `alpha = 0.8`. So your setup is between them in frequency, closer to Visual Dexterity in being slower than CoRL, but without the action smoothing used in Visual Dexterity (`ema_alpha = 1.0`).

Your success reward is `100`, added after dt scaling. CoRL and Visual Dexterity both use a sparse success coefficient of `800` in the stated reward tables. Since your shaping terms are scaled by `dt` but success is added after scaling, the effective comparison is not one-to-one; still, the papers' sparse success signal is intentionally large relative to dense shaping. The key issue is not only coefficient size: your plateau suggests the success event is almost never discovered, which is exactly the kind of problem their reset/curriculum machinery targets.

Your orientation tolerance `0.1 rad` matches CoRL's non-vision tolerance. Visual Dexterity's real-world reporting uses `0.4 rad` and `0.8 rad` thresholds, and its supplementary precision analysis shows a severe metric cliff: in-air simulation success is `72.3%` at `0.4 rad` but only `25.9%` at `0.1 rad` when using the learned stopping predictor; with ground-truth distance stopping it is `80.9%` at `0.4 rad` and `67.4%` at `0.1 rad`. That says `0.1 rad` is possible in simulation with privileged stopping/state, but very demanding once perception/stopping enters. For your privileged simulator task, `0.1 rad` is not out of family, but it makes early success rare unless starts/goals are staged.

Your actor observation is noisy low-dimensional state with joint angles, qpos error history, cube position/orientation error history, and last action. Your critic receives privileged state including true qpos/qvel, fingertip positions, true cube errors, velocities, perturbation data, and force data. CoRL's teacher actor itself receives full privileged state, including object orientation, object velocity, fingertip velocities, and goal quaternion. Their deployable reduced student still gets object position and quaternion difference but no velocities. Your actor is closer to their student than their teacher, while your critic is asymmetric. If the actor never sees enough stable contact/slip information to discover the success mode, a strong critic cannot by itself execute the missing exploration.

Your PPO uses `8192` envs, `40` rollout length, `32` minibatches, batch size `256`, `4` updates per batch, actor/value MLP `(512,256,128)`, entropy `1e-2`, and `200M` steps. CoRL's non-vision PPO used `40000` envs, episode length `300`, `8` epochs, rollout steps `8` for MLP and `50` for RNN, and larger final hidden layer `(512,256,256)` plus optional GRU. Visual Dexterity teacher used `32000` envs and batch size `64000`. This does not prove your sample budget is insufficient, because the stock LEAP baseline takes off by `~130M`, but it does mean Chen's recipes lean hard on very broad parallel exploration and, for partial observations, recurrence.

Your hand/collision geometry has taxel arrays changing fingertip/phalange collision shape, with a suspected friction-randomization mismatch because randomization may still target old `th_tip/if_tip/mf_tip/rf_tip` geom names rather than `<finger>_tip_1..16`. Both Chen papers emphasize fingertip contact material/geometry as important. Visual Dexterity explicitly says rigid hemispherical fingertips make near-point contacts, small action errors become pronounced, low friction caused slips, and soft fingertips improve contact area/compliance/friction. In their Table 1, OOD table-top `<=0.4 rad` real success improves from `45%` with rigid fingertips to `55%` with soft fingertips. Their discussion maps neatly onto your XELA issue: changing fingertip geometry can change contact patch, friction, and slip behavior enough to turn a late-takeoff baseline into a plateau.

Your task is a single cube, while Chen trains diverse objects. That cuts both ways: a cube should be simpler geometrically, but cube symmetry makes orientation success/goal representation subtle. CoRL's vision policy handles symmetry by adding Chamfer success with `theta_bar = 0.2 rad` and `d_bar_C = 0.01`; Visual Dexterity trains on asymmetric or reflective-symmetric objects to avoid multimodal pose/action labels, then only evaluates symmetric cuboid/cube later. For a cube, raw quaternion angular distance can demand one arbitrary equivalent orientation, making success sparse even when the cube "looks right" under symmetry unless the environment accounts for cube symmetries.

### What it says about our plateau

The strongest evidence is that Chen et al saw an even harsher version of your plateau: in the downward-facing no-table setup, a policy trained directly with objects underneath the hand and the same reward achieved `0%` success; the object simply fell. They diagnose this as hard exploration because the policy must learn stabilization under gravity and reorientation simultaneously. Their fix was not a small coefficient tweak; it was a curriculum/reset trick that starts from states where the grasp has already succeeded.

Your reward plateau around `145-170` looks like the "stabilization but no success" half of their diagnosis. In your case the object is not necessarily falling; it is being held well enough to harvest dense orientation/position shaping. But if the policy almost never enters `0.1 rad`, the `success_reward = 100` branch never contributes, so PPO has little on-policy evidence for the high-return behavior. Chen's evidence says that arbitrary-SO(3) in-hand reorientation can be learnable, but only after the early distribution is made forgiving enough that success is reachable.

The good-pose initialization result is directly load-bearing. CoRL trains a separate lifting policy, collects about `250` successful final grasp states per object, resets reorientation into those states with velocities zero, and only then learns downward-in-air reorientation. Without that kind of intervention, direct downward training is `0%`. With it, EGAD and YCB downward-in-air policies reach exact Table D.6 successes of `82.27 +/- 3.3` for EGAD full-state RNN and `52.81 +/- 1.7` for YCB full-state RNN before gravity curriculum; reduced-state RNN-to-RNN reaches `74.10 +/- 2.3` on EGAD and `45.22 +/- 2.1` on YCB. This is strong evidence that an RL hand may need successful grasp/reorientation-adjacent starts before the sparse success term becomes learnable.

The gravity curriculum result says the "make the start easier" principle also applies to physics, not just pose. Starting from `g = 1 m s^-1` and gradually stepping toward `-9.81 m s^-1` when success stays above `0.8` raises YCB full-state RNN from `52.81 +/- 1.7` to `74.74 +/- 1.2`, and raises reduced-state RNN student from `45.22 +/- 2.1` to `67.33 +/- 1.9`. Those are about `22` absolute percentage points. If your XELA fingertips make manipulation only slightly harder than stock LEAP, a curriculum that restores early successes could be enough to produce the missing late takeoff.

Visual Dexterity adds a second interpretation: support surfaces can be used as an exploration scaffold while reward prevents permanent dependence on them. Policies trained with support and no anti-contact penalty were poor in air: the paper reports contact-penalty policies achieved `87%` in-air success, while policies without it achieved only `4.1%`. That is a `82.9` point absolute difference. The mechanism is relevant even without a literal table: the agent may need a scaffold that makes object control easy early, plus an explicit term or schedule that removes reliance on the scaffold once orientation success is being discovered.

The fingertip/contact evidence also fits the plateau. Visual Dexterity reports failures from overshooting and finger slip, especially for OOD objects; rigid hemispherical fingertips contact over a small area and low friction caused slips. Soft fingertips improved OOD `<=0.4 rad` success from `45%` to `55%` and made behavior smoother. Your XELA taxels alter fingertip and phalange collision geometry, and your friction randomization may hit the wrong geoms. A policy that can hold but not rotate may be living in a narrow contact regime where the original LEAP affordance for rotation was destroyed or randomized incorrectly.

The success tolerance may be amplifying the issue. CoRL uses `0.1 rad` successfully in simulation, but after heavy scaffolding and privileged/reduced state. Visual Dexterity's precision analysis shows that at `0.1 rad`, success can collapse relative to `0.4 rad`: `72.3%` at `0.4 rad` versus `25.9%` at `0.1 rad` with learned stopping, though ground-truth stopping gives `80.9%` and `67.4%`. Your stock baseline proves `0.1 rad` is reachable for the original geometry, but XELA may have shifted the task just enough that `0.1 rad` successes disappear during early exploration.

### Concrete things to try

Implement a success-reachable reset curriculum first. For a cube, collect states from the stock LEAP policy or from the rare successful XELA seed where the cube is stably grasped and near manipulable. Reset XELA training from a mixture of these states with velocities zero, mirroring CoRL's about-`250` good states per object. Start with a high probability of good-pose resets, then anneal toward the real reset distribution only after the policy achieves a nontrivial success rate. This is the closest analogue to CoRL's "good pose initialization is what you need."

Add a goal-distance curriculum. Start with goal orientations close to the initial cube orientation so the `0.1 rad` success event fires early, then expand toward full SO(3). The Chen papers do not give this exact curriculum, so the schedule is not sourced from them; it is a direct application of their easier-at-start principle to your specific plateau. A conservative version: sample small relative rotations first, increase the max relative angle only when success rate is stable, and keep a replay fraction of easy goals to prevent catastrophic loss of the success behavior.

Try a gravity or effective-difficulty curriculum even for upward-facing cube reorientation if XELA geometry makes rotations unstable. CoRL's exact scheduler is: evaluate every `20` iterations, maintain `3` evaluations, require average success `>0.8` and at least `40` iterations since the last change, then step gravity by `-0.5 m s^-1` from `1` toward `-9.81`. For an upward hand this may not map literally, but reduced gravity, reduced cube mass/inertia, increased friction, or lower perturbation of initial pose can play the same role: make early successes common, then restore nominal physics.

Run an ablation with relaxed success thresholds such as `0.2 rad` and `0.4 rad`, while logging true angular-error histograms and success reward firing frequency. This is diagnostic, not necessarily the final task. Visual Dexterity's analysis shows `0.4 rad` can reveal whether the controller can generally reorient but lacks precision; CoRL's vision criterion uses `0.2 rad` plus Chamfer for symmetry. If XELA takes off at `0.2` or `0.4` but not `0.1`, the failure is precision/sparse-threshold reachability rather than basic manipulation.

Account for cube symmetries in success and/or goal error. Both papers flag symmetry as a real issue. CoRL adds Chamfer success for vision with `d_bar_C = 0.01`; Visual Dexterity avoids fully symmetric training objects and evaluates cube symmetry specially by enumerating equivalent orientations. For cube reorientation, compute angular error to the nearest symmetry-equivalent goal orientation, or add a symmetry-aware dense term. This could turn visually/physically correct cube poses into actual success events.

Fix and test fingertip friction assignment on XELA taxel geoms. The papers do not discuss `nconmax`/`njmax`, but they do repeatedly show contact geometry/material is load-bearing. Make sure domain randomization touches the actual taxel collision geoms, not legacy tip names. Compare no-randomization fixed friction, high fingertip friction, and stock-LEAP-like simplified fingertip collision proxies. If high friction or simplified fingertip geometry restores takeoff, the plateau is contact affordance rather than PPO capacity.

Add contact/proximity instrumentation before changing many RL knobs. Log which XELA geoms contact the cube, contact counts, normal forces if available, slip-like relative tangential motion if available, and whether contacts are on intended fingertip/taxel surfaces versus phalanges. Visual Dexterity's reward includes an explicit fingertip-close term because without it fingers barely contacted the object during training; your current policy may hold using contact modes that are stable but bad for rotation.

Consider recurrence or actor-side privileged/contact hints for a diagnostic run. CoRL's best reduced-state students use RNNs; their appendix says MLP-to-MLP distillation caused a `36%` success-rate drop on EGAD and `47%` on YCB relative to stronger recurrent distillation. Your actor has `history_len = 1` and no recurrence. A GRU actor or short history could help infer contact/slip state from proprioception and cube motion. A privileged-teacher diagnostic, where the actor temporarily receives true cube velocities and fingertip/contact features, would test whether the plateau is actor observability.

Revisit success reward magnitude only after success is reachable. Chen uses sparse reward coefficient `800`; your `100` post-dt reward may or may not be comparable because your shaping is dt-scaled. But if success is near-zero, coefficient tuning has little gradient. Once a reset/goal/gravity curriculum produces early successes, sweep success reward and action/energy penalties to prevent a stable-hold local optimum from dominating.

### Notable quotes and numbers

"A good pose initialization is what you need" is the CoRL subsection title for downward-facing in-air reorientation. The concrete mechanism is: train lifting, collect final successful states, reset hand and object to those states, set all velocities to `0`, and randomly sample from about `250` ending states per object during reorientation training.

Direct downward-facing, no-table training with random object placement and the same reward got `0%` success. The authors attribute this to needing to learn stabilization under gravity and reorientation at the same time.

Good-pose lifting policy success was `97.80%` on EGAD and `90.11%` on YCB. With good-pose initialization, Table D.6 downward-in-air no-DR success includes EGAD full-state RNN `82.27 +/- 3.3`, EGAD reduced RNN-to-RNN `74.10 +/- 2.3`, YCB full-state RNN `52.81 +/- 1.7`, and YCB reduced RNN-to-RNN `45.22 +/- 2.1`.

Gravity curriculum schedule in CoRL: `w_bar = 0.8`, `g0 = 1 m s^-1`, gravity step magnitude `0.5 m s^-1`, FIFO size `K = 3`, evaluation interval `L = 20`, minimum interval between gravity changes `Delta T_min = 40`, final gravity `-9.81 m s^-1`.

Gravity curriculum effect on YCB downward-in-air: full-state RNN improves from `52.81 +/- 1.7` to `74.74 +/- 1.2`; reduced-state RNN-to-RNN improves from `45.22 +/- 2.1` to `67.33 +/- 1.9`.

Visual Dexterity contact-penalty ablation: with contact penalty, in-air success was `87%`; without it, `4.1%`. The source explicitly says the contact penalty benefits in-air reorientation.

CoRL non-vision reward constants: `c_theta1 = 1`, `c_theta2 = 800`, `epsilon_theta = 0.1`, `theta_bar = 0.1 rad`, action-penalty magnitude listed as `0.1` with sign inconsistency in the text/table. CoRL lifting constants: `c_h1 = 0.05`, `epsilon_h = 0.02`, `h_bar = 0.04`, `c_h2 = 800`.

Visual Dexterity reward constants: `c1 = 800`, `c2 = 1`, `c3 = -1`, `c4 = -20`, `c5 = -100`, `c6 = -1`, `c7 = -2`, `epsilon_theta = 0.4 radians`, `p_bar = 0.15`, `p_bar_z = 0.16`, `qdot_bar = 0.25`, `v_bar = 0.04`, `omega_bar = 0.5`. Numeric training `theta_bar` and `a_bar` are not stated in the extracted text.

CoRL PPO: `40000` envs, episode length `300`, `8` PPO epochs, GAE `0.95`, discount `0.99`, actor LR `0.0003`, critic LR `0.001`, PPO clip `0.1`, rollout steps `8/50` for MLP/RNN, value loss coefficient `0.0005`, entropy coefficient `0`.

Visual Dexterity PPO teacher: `32000` envs, batch size `64000`, `8` rollout steps per update, `12` policy epochs per rollout, GAE `0.95`, discount `0.99`, actor LR `0.0003`, critic LR `0.001`, PPO clip `0.1`.

Control frequency/action: CoRL uses `60 Hz`, `20`-D relative joint target changes, clamp `|Delta q_target| <= 0.33 rad`. Visual Dexterity uses `12 Hz`, `3G`-D relative joint target changes, EMA action smoothing `alpha = 0.8`, and `q_tgt_{t+1} = q_t + a_bar_t`.

Fingertip/contact material: Visual Dexterity reports OOD real table-top `<=0.4 rad` success improves from `45%` rigid fingertips to `55%` soft fingertips, while train objects stay about similar (`81%` rigid, `79%` soft). They attribute failures to overshoot and slipping; soft fingertips increase friction/compliance/contact area and produce smoother motion.

Precision numbers from Visual Dexterity: in-air simulation over `1200` tests on `12` objects is `72.3%` successful at `0.4 rad` but `25.9%` at `0.1 rad` with learned stopping; using ground-truth distance to stop gives `80.9%` at `0.4 rad` and `67.4%` at `0.1 rad`. Among actual `Delta theta <= 0.1 rad` points, only `29.4%` of predicted distances were also within `0.1 rad`; among actual `Delta theta <= 0.4 rad`, `85.9%` were predicted below `0.4 rad`.

Contact/collision fidelity: both papers use Isaac Gym and V-HACD convex decomposition. CoRL uses V-HACD for object meshes; Visual Dexterity uses V-HACD for object and robot-hand meshes with resolution `100,000`. Visual Dexterity explicitly warns that fast simulator contact models are crude approximations, especially for non-convex objects. Neither source states MuJoCo-style contact budgets such as `nconmax`, `njmax`, or solver settings.
