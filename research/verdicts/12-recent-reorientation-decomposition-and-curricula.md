## 12 -- Recent reorientation decomposition and curricula: verdict

**Overall:** analysis/12 SUPPORTS the two INTERIM verdicts on the reward kernel and open levers, but REFINES the project map: arbitrary-goal reorientation should not be treated as one more scalar-reward ablation after this many nulls. The strongest surviving move is ACTION-SPACE structure: a planner over reusable axis-rotation skills plus residual action, because this repo already has `rotate_z` at 2.19 rad/s in run 15 and `rotate_x` at 2.217 rad/s in run 18 on the same hand and pads, while monolithic reorient remains 0/32 deterministic successes with a 25-30 deg stall. The cheap move is TASK-DISTRIBUTION structure: DexNDM-style intermediate waypoint goals along the residual tip axis. The termination penalty is an OPEN confound worth isolating. None of this contradicts the equilibrium account in `research/STATE.md`; it adds a third category beside COST and WORTH: changing the ACTION SPACE searched by PPO.

### Cost of a skill-hierarchy route here

Existing pieces are real but incomplete. `tasks/rotate_z/config/__init__.py:10-19` registers `Mjlab-LeapXELA-Cube-RotateX`, `RotateY`, and `RotateZ` from one axis-parameterized factory, not separate `tasks/rotate_x/` or `tasks/rotate_y/` packages; `find leapXelaMjLab/src/leap_xela_mjlab/tasks -maxdepth 2` shows only `reorient/` and `rotate_z/`. Run 15 `rotatez-3000` reached `Episode_Reward/angvel = 2.19 rad/s` with 0.17 drops/episode (`TRAINING_NOTES.md:463-478`, `559`). Run 16 `rotate_x` at condim 3 reached only 0.284 rad/s with 3.93 drops/episode, run 17 `rotate_y` reached 0.575 rad/s with 2.31 drops/episode and was explicitly not converged (`TRAINING_NOTES.md:559-569`), and run 18 `rotatex-condim6` reached 2.217 rad/s with 0.52 drops/episode (`TRAINING_NOTES.md:577-593`). So `+/-z` and `+/-x` are usable candidates; `+/-y` is OPEN, not a finished primitive.

What must be built:

- Skill-conditioning interface, OPEN / ACTION-SPACE / 2.0-3.0 days: load frozen rotate policies, expose a discrete skill command `+x/-x/+y/-y/+z/-z/STOP`, normalize skill observations exactly as the trained rotate envs expect, and convert sign by either signed reward/policy pairs or action negation only if validated. Current rotate actor obs are only `joint_pos` and `last_action` (`tasks/rotate_z/config/env_cfg.py:59-67`), with action shape 16 (`env_cfg.py:112-121`), so the low-level policy can be run as a black-box action generator, but checkpoint wiring and obs-normalizer compatibility still need code.
- Planner observation space, OPEN / ACTION-SPACE / 1.0-1.5 days: reuse reorient actor ingredients plus goal-relative pose. The current reorient actor is 57-D: joint pos, joint-pos error, cube-pos error, cube-orientation error, last action (`tasks/reorient/config/env_cfg.py:128-149`), with critic-only velocities at `env_cfg.py:151-184`. From Simple to Complex uses object pose, relative goal transform/history, prior planner actions, proprioception, and skill feedback; minimal local version should include current cube quat/goal relative rotation, cube position error, joint pos, last action, previous skill, and optionally the skill action.
- Residual action head, OPEN / ACTION-SPACE / 1.0-2.0 days: final action must be `a_skill + a_res`. Current action integration is one continuous 16-D raw action scaled by 0.5 and clipped to ctrl limits (`tasks/reorient/mdp/actions.py:75-84`, `tasks/reorient/config/env_cfg.py:203-212`). The lowest-surgery implementation is an env/action wrapper that receives planner residual action and skill id, evaluates the frozen skill policy, sums/clamps before `DeltaJointPositionAction.process_actions`, and keeps PPO seeing one continuous action. A faithful paper version needs mixed categorical plus continuous actions.
- rsl_rl / mjlab structural fit, OPEN / ACTION-SPACE / 2.0-4.0 days: current task/runner is single-level PPO. Runtime eval logs show `ActionManager` has one active 16-D `joint_pos` action and the actor is `MLPModel(57 -> 16)` with `GaussianDistribution`; code config matches that in `tasks/reorient/config/rl_cfg.py:26-35` and training uses `MjlabOnPolicyRunner` with `RslRlVecEnvWrapper` (`scripts/train.py:20`, `280-285`). There is no registered native two-head categorical-plus-continuous policy in this repo. Minimal hierarchy does not require major surgery if encoded as an env wrapper or a continuous 23-D action whose first 7 dims are interpreted as skill logits outside PPO; a clean categorical distribution and proper log-prob accounting would require runner/model/distribution work.
- Rotate_y completion, OPEN / ACTION-SPACE / 0.5-1.5 days plus one training run: existing run 17 was still climbing and explicitly lower-bound only (`TRAINING_NOTES.md:568-569`). A hierarchy over six axes should not be judged until `RotateY` is converged under the better condim/contact choice or replaced with a demonstrated `RotateX`-only/`RotateZ`-only reduced planner.
- End-to-end train/eval harness, OPEN / ACTION-SPACE / 1.0-2.0 days: register `Mjlab-LeapXELA-Cube-Reorient-Hierarchy`, dump configs/checkpoint paths, add deterministic eval that logs skill switches/residual norm and the spin/tip split already used by `eval_policy.py`.

Honest total: 7.5-14.0 engineering days before the first serious training run, not counting GPU time. This is too expensive to outrank the reward-kernel and waypoint tests, but it is the most structurally credible route if cheap tests keep returning conservation-law nulls.

### Still open from this source

- ACTION-SPACE: minimal skill hierarchy over frozen `RotateX/Y/Z` policies plus residual action; cost 7.5-14 engineering days plus training; prediction best error <=17 deg, total closure >=87%, tip closure >=80%, >0/32 successes; falsified by 24-30 deg and conservation-law spin/tip reallocation.
- TASK-DISTRIBUTION: DexNDM-style 90 deg intermediate waypoint along the residual tip axis; cost 0.5-1.0 day plus one run; prediction tip closure >=78%, best <=20 deg, >0/32 successes; falsified by best 24-30 deg with 0/32.
- COST: termination penalty -100 -> -10 or 0 as a single isolated variable; cost 0.25 day plus one run; prediction more early drops but >3 deg improvement or nonzero deterministic success; falsified by same error band plus higher drops.
- COST: `action_rate` weight -0.001 -> 0, still unrun; cost 0.25 day plus one run; prediction under strict equilibrium is another rebalance, but if total closure leaves 81.4% the cost side is live.
- WORTH: replace the orientation kernel with inverse distance, not long-tail; cost 0.5 day plus one run; prediction total closure leaves 77.6-81.4% and success becomes nonzero; falsified by another spin/tip reshuffle.

### Ranked recommendation

1. Implement the DexNDM-style tip-axis waypoint first: it is distinct from the existing random drift, cheap, and aimed directly at the 96% tip-over residual.
2. Run the inverse-distance orientation kernel from INTERIM 00: analysis/12 independently supports that reward shape, and it is the cleanest WORTH-side test.
3. Drop or reduce `termination=-100` as one isolated run: DexReMoE makes the exploration-suppression confound concrete, and this project’s per-goal-timeout idea is already confounded by that penalty.
4. Run `action_rate=0`: still the dominant logged scalar cost, but it is lower value than waypoint/kernel because it remains a cost-side intervention.
5. Build the skill hierarchy only after the cheap tests: it is the best structural explanation and the closest match to From Simple to Complex Skills, but the local cost is at least 7.5-14 engineering days and `rotate_y` is not yet a completed primitive.
