## 02 -- mjlab working LEAP pipeline: verdict

**Overall:** The Msornerrrr pipeline SUPPORTS the reward-equilibrium account in `00-INTERIM-reward-kernel.md`: it avoids our sparse-threshold bottleneck by paying clipped drift-gated yaw rate every step and has no active success threshold (`research/analysis/02-mjlab-leap-working-pipeline.md:34`, `research/analysis/02-mjlab-leap-working-pipeline.md:42`, `research/analysis/02-mjlab-leap-working-pipeline.md:220`). It REFINES `01-INTERIM-open-levers.md`: its working recipe uses weaker early penalties and stricter bad-motion terminations, so "cost of precision" is still live, but the right curriculum gate in our setup cannot be success rate because our logged success stays `0.03-0.05` goals/episode (`research/STATE.md:53`, `research/analysis/02-mjlab-leap-working-pipeline.md:67-71`). It CONTRADICTS simple physics/contact explanations: our repo has already tested `condim=6`, friction, cube size, action L2, entropy/noise, and observation-noise variants; all deterministic reorient evals stay 0/32 with best errors clustered around 24.8-30.1 deg except deliberately bad variants (`leapXelaMjLab/TRAINING_NOTES.md:107-116`, `leapXelaMjLab/TRAINING_NOTES.md:1460-1466`, `leapXelaMjLab/eval/run14_det.json:29`, `leapXelaMjLab/eval/run14_det.json:65`). Bluntly: their source is a real same-stack positive control, but it is a yaw-rate task, not arbitrary target-quaternion reorientation; the surviving value is the dense progress objective, progress-gated penalties, strict drift termination, and smoother action path.

### Still open from this source

- Dense yaw-progress auxiliary/bootstrap: (a) changes what progress/precision is worth, because reward is paid on useful yaw motion before any sparse success (`research/analysis/02-mjlab-leap-working-pipeline.md:34`, `research/analysis/02-mjlab-leap-working-pipeline.md:256`); (b) cost M; (c) confirm if deterministic median best error reaches <=18 deg or total closure exceeds 85% within 1500 iterations, refute if it stays 24.8-30.1 deg and 0/32.
- Progress-based penalty curriculum with the right gate: (a) changes cost of precision by keeping linvel/pose/torque/work penalties weak until continuous progress appears (`research/analysis/02-mjlab-leap-working-pipeline.md:67-71`); (b) cost M; (c) use drift-gated normalized orientation-error reduction or average positive yaw/rotation-vector progress per episode, confirm if best improves >=5 deg within 1500 iterations, refute if costs fall but best does not move.
- Strict physical drift terminations: (a) changes task/state distribution and removes reward from uncontrolled motion, related to but broader than per-goal timeout (`research/analysis/02-mjlab-leap-working-pipeline.md:73-78`); (b) cost S; (c) confirm if episodes with large cube drift/tilt vanish and best error improves >=4 deg without extra drops by 1500 iterations, refute if mean episode length falls and best error worsens.
- Small delta action with substep interpolation: (a) changes cost of precision by reducing abrupt target jumps (`research/analysis/02-mjlab-leap-working-pipeline.md:116-123`); (b) cost M; (c) confirm if drift-after-best p90 drops >=30% and best <=21 deg by 1500 iterations, refute if smoother actions merely slow approach.
- Exact solver-conservative diagnostic: (a) changes cost of precision/contact accuracy; (b) cost M/L, likely >=4x wall-clock from timestep and iteration counts alone; (c) confirm if best error leaves the 24.8-30.1 deg band, refute if only throughput worsens.
- Grasp-cache/narrowed reset: (a) changes task/state distribution by starting from known stable grasps (`research/analysis/02-mjlab-leap-working-pipeline.md:84`); (b) cost L for cache, S for narrow-only; (c) confirm if deterministic success becomes nonzero and early drops decline, refute if lower drops do not move best error.
- Broad shared friction/contact DR over all actual contact geoms: (a) changes task/state distribution/robustness, not basic precision worth (`research/analysis/02-mjlab-leap-working-pipeline.md:86`); (b) cost M; (c) confirm if policy becomes less sensitive to priority/friction eval sweeps and best improves >=4 deg, refute if headline stays null and spin/tip reallocation repeats.

### Ranked recommendation

1. Replace/augment the reward with dense progress, preferably `1/(err+0.1)` from `00` first and yaw-progress as a bootstrap second: expected effect >=8 deg best-error improvement or total closure leaving 81.4%; cost M. This is the only category the same-stack working pipeline strongly SUPPORTS and the nulls have not killed.
2. Add a progress-gated penalty curriculum using a continuous gate, not success rate: expected effect 4-8 deg if terminal correction is currently over-penalized; cost M. Gate on drift-gated normalized error reduction/yaw progress so it is nonzero from run-14-style approach behavior.
3. Add strict cube speed/position/tilt termination as a diagnostic next to, not instead of, per-goal timeout: expected effect 3-6 deg if parking/uncontrolled drift is being rewarded; cost S. This REFINES the `01` timeout verdict into a broader bad-progress/bad-drift termination family.
4. Port the small `+/-1/24` action delta with substep interpolation: expected effect mostly stability, maybe 0-5 deg; cost M. Action L2 already says action saturation alone is not the bottleneck, so do not rank this above reward/curriculum.
5. Run the full conservative solver/contact-param bundle only after reward/curriculum: expected effect 0-5 deg with high wall-clock cost; cost M/L. Buffer overflow is already dead, so this is an accuracy check, not the lead hypothesis.
6. Build grasp-cache/narrow reset only if dense progress still fails: expected effect discriminates initial-state difficulty from terminal precision, but it changes the task/state distribution and costs more engineering; cost L.
